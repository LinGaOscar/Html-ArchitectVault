Cache 讀寫策略

把常讀的資料放進 Cache 可以減輕 DB 的負擔。問題是資料被改寫時，Cache 和 DB 該由誰先更新、什麼時候更新？這個選擇決定寫入快不快、讀到的資料新不新，以及 Cache 故障時會不會掉資料。

三個面板收到同一串操作，key 都是 user:1，起始時 DB 存 v1、Cache 是空的。留意每個請求牌先飛到哪裡、Cache 的值怎麼變，以及 DB 區的讀寫次數最後差多少。

重點整理

Cache-Aside
由應用程式管 Cache。讀取 miss 時自己回源 DB 並回填；寫入時先寫 DB，再把 Cache 的舊值刪除（invalidate）。刪除而不是更新，是因為下一次讀取會從 DB 載入最新值。代價是寫入後的第一次讀取一定 miss，會多打一次 DB。
Write-Through
寫入時同步寫 Cache 與 DB，兩邊都完成才回應，所以 Cache 與 DB 保持一致，也不會因 Cache 故障掉資料。代價是每次寫入都要等 DB。
Write-Back（Write-Behind）
寫入只寫 Cache 並標 dirty，立刻回應，之後再批次 flush 到 DB。寫入最快，多次寫入同一個 key 還能合併成一次 DB 寫入。代價是 flush 之前 DB 落後 Cache，若 Cache 此時故障，尚未寫回的資料就遺失。
